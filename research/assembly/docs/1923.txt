#1923  Supervisor's adapter, throttling, snapshot, swap, sanitising, allowlist and mock shapes are worth carrying with their caveats; its push-only protocol, per-app client sockets, CDN loads, bare wire envelope and fake-shaped tests are not; the uncommitted files hold one lesson
  finding · active · #research · #supervisor-lessons · superintendent · revised once by @claude-super on Thu 3 Sep

**Summary.** Supervisor (private repo, 14 commits, stalled 2026-04-15) contributes eight reusable shapes, each with a caveat verified in code or by measurement: an adapter object per app subscribing to the app's own event emitter; the adapter's socket and serialisation on their own loop, on a daemon thread for a threaded host; a dirty-flag broadcast loop with heartbeat and a client stale timer; manifest then state snapshot on connect; atomic reference swaps across threads; numpy sanitising at the JSON boundary; allowlisted file serving behind a realpath guard; and a mock server per app. One test practice is worth keeping as well: asserting `json.dumps` on the real `get_state()`. Left behind: the push-only protocol, the one-socket-per-app client with hard-coded prefixes, CDN imports and a fixed 2 s retry, sequential per-client sends, the bare envelope `web_ui.py` speaks, and adapter tests whose fakes described the interface the adapter wanted while the real caller passes a list as the player and `None` as the recorder, so voices, queue depth and audio serving were dead in production. Two things the code teaches by being wrong: a bind failure in the threaded start never reaches the caller, and the Subsample adapter takes the audio callback's lock. The uncommitted `core.py` change (state immediately after the manifest) is the snapshot-on-connect lesson, learned last and never committed; the other two uncommitted files are dashboard cosmetics.

The snapshot must read current state, never an accumulator: `after_broadcast()` (`substation.py:196-198`) marks channels for replacement only after a send, so with no client attached the peak merge at `substation.py:117-129` accumulates until someone connects and their first frame shows the maximum SNR since the last client left. |

| Never take a real-time thread's lock from the adapter | `subsample.py:158-166` | The lesson for the pads and voices display in `subsample-substation`: the app publishes a snapshot by swap and the adapter reads it | `get_state()` takes `player._voices_lock` on the Supervisor thread. A Python thread iterating voices and building dicts under it can hold the audio callback for a GIL switch interval, a priority inversion against the real-time thread. `README.md:208` forbids locks for the wrong reason (stalling the loop). ## Not worth carrying

**Push-only.** `core.py:191-192` and `web_ui.py:150-151` both `async for` over inbound frames and drop them. Nothing in the protocol, adapters or client has a command path, so nothing here informs `state-sync`.

**CDN and font dependencies.** Preact and htm from `https://esm.sh` in `client/app.js:1-3` and ten of the twelve other client modules (`components/utils.js` and `panels/registry.js` have none); JetBrains Mono from Google Fonts (`client/index.html:7-9`). Only Gridstack is vendored (`client/lib/`, with its `LICENSE.txt`). A local studio tool stopped working without internet.

**One socket per app, aggregated in the browser.** `DEFAULT_CONNECTIONS` hard-codes three `ws://localhost` URLs (`app.js:10-14`); `ConnectionManager` holds a socket, manifest, state, retry timer and stale timer per app (`app.js:69-193`); `APP_COLORS` (`16-20`), `panelIdToApp` (`480-490`) and the panel import list (`495-504`) hard-code app prefixes, so adding an app is four edits in `app.js` plus a CSS variable plus the panel module (`README.md:305-322`). `wsUrlToHttp` (`475-478`) rewrites each app's URL for audio, so the browser must reach every app host directly. This is the shape `topology` weighs; its cost is visible in the client. The reconnect behaviour is not worth carrying as code either: a fixed 2 s retry with no backoff (`app.js:177-183`) from `onclose` (`130-136`) and from a constructor throw (`99-105`), `onerror` a no-op (`138-140`), and no resync beyond whatever the server sends on connect. `transport-ui` asks for backoff and full resync; specify those rather than porting these.

**Wire incompatibility with `web_ui.py`.** `web_ui.py:194-196` broadcasts `json.dumps(state)` of the bare dict built at `206-222`, with no `type` key and no manifest, bound to `127.0.0.1` by default (`web_ui.py:41`). The client acts only on `type === 'manifest'` or `'state'` (`app.js:119-126`), so every Subsequence frame is parsed and discarded. The field names match `mock_sequencer.py:33-72` exactly and the attributes read exist (`_drum_note_map` at `composition.py:5967`, `_muted` at `5974`, `length` at `pattern.py:130`), so the incompatibility is the envelope alone. `README.md:337-341` records Subsequence as "mock only". The lesson is one envelope, defined once, that every producer and the client are tested against.

**Adapter tests that never exercised the real call.** All 37 tests pass. The real caller (`subsample/cli.py:1750-1756`) passes `player=_player_cell`, a one-element list, and `recorder_processor=None`, because the player is created later on its own thread (`cli.py:1269`, `1336`). Confirmed by constructing the adapter with those arguments (`probe_wiring.py`): `hasattr(player, 'events')` is false so the CC subscription at `subsample.py:89-90` never runs (`cli.py:1271-1272` and `1338-1339` patch `_on_cc` in later); `hasattr(self._player, '_voices_lock')` is false forever (`subsample.py:158`) so `voices` is always empty; `queue_depth` is always 0 (`subsample.py:194-195`) although `recorder.py:292` provides it; and `serve_dirs` is empty as above. The fixtures (`tests/conftest.py:61-104`) give a `FakePlayer` with `_voices_lock` and `events`, a `FakeRecorder` with `queue_depth`, and a `FakeSamplerConfig` with `output.directory`: the interface the adapter wanted, not what `cli.py` passes. The specification counted two wiring defects; it is three broken features from two bad arguments plus one stale config path. Substation's wiring is sound: every attribute read at construction exists (`scanner.py:88`, `99`, `115-116`, `146`, `151`). The lesson: the constructor signature is part of the contract, and one test constructs the adapter the way the entry point does.

**A README that drifted.** `README.md:334` lists `channel_state` among the events the Substation adapter consumes; it subscribes to five others (`substation.py:79-83`). `README.md:343-345` says the Subsample module is "not yet created (mock only)"; it exists, committed in `999a1aa` and wired from `subsample/cli.py:1749-1759`. The README describes the tree before the last commit. #613 keeps intent in test docstrings and README-AGENTS; Superintendent's own must be checked against the code they describe.

## Version facts that bear on the neighbours

websockets 13.0 (2024-08-20) introduced `websockets.asyncio.server`; 14.0 (2024-11-09) made it the default behind `websockets.serve` and deprecated the legacy implementation, which is still present through 17.1 (2026-08-26) (https://websockets.readthedocs.io/en/stable/project/changelog.html). Supervisor's `>=13.0` floor is below the 14.0 its `process_request` signature needs; Subsequence's `websockets>=12.0` (`pyproject.toml:23`) is below the 13.0 its `import websockets.asyncio.server` (`web_ui.py:21`) needs, as the specification warned.
